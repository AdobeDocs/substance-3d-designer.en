# Learn about terms and concepts used in Designer.

## &#35;

|  |  |
| --- | --- |
| <b><a name="three-d-scene"></a>3D scene</b> | A collection of objects and data involved in representing and animating a visualisation of 3D space:<ul data-preserve-html="true"> <li data-preserve-html="true">[Meshes](#mesh)</li> <li data-preserve-html="true">[Materials](#material)</li> <li data-preserve-html="true">Cameras</li> <li data-preserve-html="true">Lights</li> <li data-preserve-html="true">Animation</li> <li data-preserve-html="true">Simulations</li> <li data-preserve-html="true">...</li> </ul>[Popular file formats](https://www.adobe.com/products/substance3d/discover/3d-files-formats.html) to store 3D scenes include Pixar's [USD](#usd) and Autodesk's FBX. All file formats do not support all these components |

## A

|  |  |
| --- | --- |
| <b><a name="alpha"></a>Alpha channel</b> | The fourth channel of a color image, often used to describe opacity. |
| <b><a name="ambient-occlusion"></a>Ambient occlusion</b> | The attenuation of ambient light on surfaces that are less exposed and therefore harder to reach. |
| <b><a name="anisotropy"></a>Anisotropy</b> | The property of being dependent on direction. In other words, providing a different result when measured or observed on a different axis.<br><br>Anisotropic materials have a different look depending where they are looked from, and anisotropic filters are not applied uniformally in all directions. |
| <b><a name="aov"></a>AOV</b> | Arbitrary Output Variable (AOV) is a term used in [rendering](#rendering) to describe additional data channels that can be output from a render, such as depth, normals, or custom data.                                                                                                                                                                                                                                                                                                                                                                                            |
| <b><a name="api"></a>API</b> | An Application Programming Interface (API) is a collection of functions and procedures which lets users access the functions and procedures of another application of program.<br><br>An API provides a controlled and secure layer between the user and a program. It may also use another programming language to make that program easier to interact and more widely accessible.<br><br>Designer offers a [Python API](../scripting/scripting.md) which provides easy access to a wide range of its capabilities for manipulating data, building custom tools and accelerating workflows. |
| <b><a name="atomic-node"></a>Atomic node</b> | The fundamental building blocks of graphs. All [instance nodes](#instance-node) can be broken down into graphs of atomic nodes.<br>Each graph type has its own set of atomic nodes. |

## B

|  |  |
| --- | --- |
| <b><a name="baking"></a>Baking</b> | The process of computing information out of a 3D model and storing the results into a [texture](#texture). The data is placed in the texture according to the model's [UVs](#uv). |
| <b><a name="base-color"></a>Base color</b> (Albedo) | A channel of a [material](#material) defined using the PBR Metallic Roughness [shading](#shader) model.<br>Base color specifies the color of a surface without any lighting information.<br><br>It should not be confused with [Diffuse](#diffuse). |
| <b><a name="base-parameter"></a>Base parameter</b> | A parameter common to all nodes in a Substance graph that compute a [bitmap](#bitmap).<br><br>These include core aspects of the bitmap, such as its resolution ([Output size](#output-size)) and [bit depth](#bit-depth) (Output format), or how the bitmap is computed such as [tiling](#tiling) mode.<br><br>Base parameters are often [inherited](#inheritance) from other nodes upstream or the graph hosting the node. |
| <b><a name="bilinear-filtering"></a>Bilinear filtering</b> | An interpolation process used in computer imaging when a [texture sample](#texture-sampling) is not performed exactly at the center of a pixel.<br><br>For instance, this may occur when an image is enlarged. |
| <b><a name="bit-depth"></a>Bit depth</b> | The number of bits used to store the value of a pixel in a texture. Higher bit depths allow more values to be encoded, resulting in smoother gradients.<br><br>Different bit depths are available depending on the type of the value: - Integer values can be encoded using 8 bits (0 to 255) or 16 bits (0 to 65,535). - Floating point values can be encoded using 16 bits (+32767.9999 to -32768.0  ) or 32 bits (-3.4E+38 to +3.4E+38)<br><br>Low dynamic range images use integer values to encode steps from 0 to 1. High dynamic range images use floating point values to encode raw numerical values.<br><br>In Substance graphs, bit depth is controlled by the Output Format parameter. |
| <b><a name="bitmap"></a>Bitmap</b> | A digital image. Two types of images are most common:<ul data-preserve-html="true"> <li data-preserve-html="true">Grayscale images have only one channel: luminance (L);</li> <li data-preserve-html="true">Color images have three channels: red, green and blue (RGB). A fourth one may be present: alpha (A) which is often used for opacity. Color images in Designer are always RGBA.</li> </ul>  Bitmaps may be thought of as grids of values. Each cell of that grid is a pixel, which is short for 'picture element'. A pixel stores one value per channel. The type of that value depends on the [bit depth](#bit-depth) of the bitmap. |

## C

|  |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --- |--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><a name="cache"></a>Cache</b> (Memory) | A collection of data – E.g. node's [base parameters](#base-parameter) and output images – stored in memory to be reused.<br><br>Cache greatly speeds up graph computations by letting the [Substance Engine](#substance-engine) only recompute the parts of a graph that have changed. When tweaking node connections and parameters, all the nodes that precede it are not impacted by those changes, thus do not need to be [evaluated](#evaluation) again to update the graph. Their cache is used instead.<br><br>The cache can have a significant memory footprint when working with high resolutions and bitdepths in large graphs.                                                                                                                                                      |
| <b><a name="channel-packing"></a>Channel packing</b> | An optimisation technique where separate images are packed into the RGB(A) channels of a single color image.<br><br>For instance, an RMA texture is a roughness map (R), metalness map (M) and ambient occlusion map (A) all packed into a single color texture.<br><br>Another common technique is packing a grayscale texture into the blue channel of a normal map, as the blue channel – I.e., the 'Up' component of the normal vector – can be recomputed at runtime.<br><br>The [RGBA merge](../compositing-graphs/nodes-reference-for-com/node-library/filters/channels/rgba-merge/rgba-merge.md) node is useful for implementing this technique.                                                                                                                                            |
| <b><a name="color-space"></a>Color space</b> | A definition of how a range of colors is represented.<br>Digitally encoding and decoding a specific color requires such a definition to make sense of the numbers used.<br><br>An image file stores color values using a specified color space, so that these colors can be reproduced faithfully on a display that supports that color space. A display has specific color reproduction capabilities that allow it to fully or partially support a given color space.<br><br>Raw data – E.g. a normal map – is always encoded and decoded in a Linear color space because these colors are not meant to be visualised and no transformations should be applied to that data.<br><br>sRGB is a widely supported color space. Others popular color spaces include Adobe RGB, Rec. 2100 and ProPhoto RGB. |
| <b><a name="content-credentials"></a>Content credentials</b> | An industry-standard and secure metadata providing information about the life of a piece of content (image, audio file, etc.).<br>Content credentials helps tracing content back to its creator, can keep track of edits and tools used in producing that content, and informs artists and audiences alike about the content they consume and reuse, promoting accountability and credit. Learn more [here](https://contentcredentials.org/).                                                                                                                                                                                                                                                                                                                                            |
| <b><a name="cooking"></a>Cooking </b>(<a name="compilation"></a>Compilation) | The process of translating data into another language so it can be executed quickly and efficently.<br>Computing the result of a Substance graph requires compiling it first. Compilation is part of the graph [evaluation](#evaluation) process.<br><br>This compilation is performed on a flattened graph, which means all [instance nodes](#instance-node) are 'replaced' by their source graphs so that one larger graph remains, and that graph is what is compiled.<br><br>A compiled graph is not editable. Exposed parameter remain available if they are [dynamic](#dynamic-parameter), while [static](#static-parameter) parameters are locked and hidden.                                                                                                                              |
| <b><a name="culling"></a>Culling</b> | An optimization technique for rendering 3D scenes which removes geometry from a render's computations when it is not visible.<br><br>This may include objects or polygons outside of the camera's frustum (*frustum culling*), facing the oppsite way from the camera (*backface culling*) or completely hidden by other opaque objects (*occlusion culling*).                                                                                                                                                                                                                                                                                                                                                                                                                            |

## D

|  |  |
| --- | --- |
| <b><a name="dependency"></a>Dependency</b> | A file A that is used by another file B in such a way that file B does not work as intended when file A is missing.<br><br>A dependency of a [package](#package) can be another package because it references a graph inside it, an image file, a font, etc.<br><br>A package stores the path to its dependency, and a warning is raised if the dependency cannot be found at that path. Missing dependencies can also result in [ghost instance nodes](#ghost-instance-node) in a graph. |
| <b><a name="diffuse"></a>Diffuse</b> | A channel of a [material](../glossary/glossary.md) defined using the PBR Specular Glossiness [shading](#shader) model. Diffuse specifies the color of a surface when lit.<br><br>It should not be confused with [Base color (Albedo)](#base-color). |
| <b><a name="directx"></a>DirectX</b> | A collection of APIs for handling multimedia content. Its 3D API, Direct3D, is widely used in video game development and other 3D industries.<br><br>Direct3D places the origin of a texture – I.e., its (0, 0) coordinate – at the *top left*, (Y-down) whereas the [OpenGL](#opengl) API places it at the *bottom left* (Y-up).<br><br>This means a DirectX normal map has an *inverted green channel* compared to OpenGL. Indeed, the green channel hosts the normal vectors' Y-coordinate. |
| <b><a name="displacement"></a>Displacement</b> | The process of moving the [vertices](#vertex) of a 3D model, often along their [normal](#normal).<br><br>Displacement is often used in combination with [tessellation](#tessellation) and [normal maps](#normal-map) to model finer detail on a surface. |
| <b><a name="dynamic-parameter"></a>Dynamic parameter</b> | A parameter which value may change. In other words, any parameter which value is not constant is dynamic.<br><br><br>This includes exposed parameters, any parameters impacted by an exposed parameter, and any parameter value that is impacted by [sampling in a texture](#texture-sampling).<br><br>Contrarily to [static parameters](#static-parameter), the value of dynamic parameters can be adjusted on the fly after the graph is compiled into an SBSAR file. |

## E

|  |  |
| --- | --- |
| <b><a name="evaluation"></a>Evaluation</b> | The process of resolving the propagation of data and parameters in the graph. Evaluation verifies the validity of a graph and its connections, applies [inheritance](#inheritance), and [cooks](#cooking) the graph.<br><br>In the Graph View, a connection is represented with a dotted line when it is not evaluated.<br>Evaluation turns connection into solid lines.<br><br><br>Every time a parameter is adjusted in a graph, the node hosting this parameter and all nodes downstream are [invalidated](#invalidation) and need to be re-evaluated before being [rendered](#rendering). |

## F

|  |  |
| --- | --- |
| <b><a name="filter"></a>Filter</b> (Node) | A node which applies a modification to an image (E.g., a deformation) or extracts information out of it (E.g., a mask). |

## G

|  |  |
| --- | --- |
| <b><a name="ghost-instance-node"></a>Ghost instance node</b> | An [instance node](#instance-node) referencing a subgraph that cannot be found – I.e., a missing [dependency](#dependency) – is loaded as a ghost instance node.<br><br>Ghost instance nodes are restored to their expected state by resolving the missing dependency and reloading the [package](#package). |
| <b><a name="glossiness"></a>Glossiness</b> | A channel of a [material](../glossary/glossary.md) defined using the PBR Specular Glossiness [shading](../glossary/glossary.md) model. Glossiness specifies the rugosity of a surface – I.e. microscopic variations of height, also called *microfacets*.<br><br>High glossiness results in a smooth look, while low glossiness results in a rough, matte look.<br><br>It is the inverse of [Roughness](#roughness). |

## H

|  |  |
| --- | --- |
| <b><a name="histogram"></a>Histogram (image)</b> | In the context of an image, a histogram represents the population of the values in a give range – often &#91;0, 1&#93;.<br><br>This population is visualized using vertical bars where a value more present in the image results in a higher bar for that value.<br>The bars are distributed horizontally from low values (dark) to high values (bright).<br><br>Histograms of color images usually overlap the histograms of each of their channels – typically R, G, B. |

## I

|  |  |
| --- | --- |
| <b><a name="inheritance"></a>Inheritance</b> | In the context of Substance graphs, inheritance describes the property of nodes acquiring parameter values from their upstream nodes, or their parent graph.<br><br>Inherited parameters include [resolution](#resolution) ([Output size](#output-size)), [bitdepth](#bit-depth) ([Output format](#output-format)) and [tiling](#tiling) mode.<br><br>Learn more about inheritance in this [dedicated page](../compositing-graphs/inheritance-compositing/inheritance-in-substance-compositing-graphs.md). |
| <b><a name="instance-node"></a>Instance node</b> | An instance node represents a graph A into another graph B. In that case, graph A may be called a [subgraph](#subgraph) of graph B. Any change in graph A is propagated to all instance nodes that represent it.<br><br>The instance node applies its own set of values for the input parameters of graph A in the context of graph B. In that sense, graph B can host multiple instance node that all reference graph A, but each pass different values or textures as inputs into graph A.<br><br>All nodes in Designer's Library that are not [atomic nodes](#atomic-node) are instance nodes. |
| <b><a name="invalidation"></a>Invalidation</b> | The process declaring that the result of a node is outdated.<br><br>When a parameter is adjusted, the node hosting this parameter and all nodes downstream are invalidated, thus need to be [evaluated](#evaluation) and [rendered](#rendering) again. |

## M

|  |  |
| --- | --- |
| <b><a name="material"></a>Material</b> | The collection of properties and behaviours of matter in space, which includes surfaces and volumes.<br>The appearance of an entity in 3D space is defined by its material.<br><br>Materials may be defined in various ways, and all definitions do not support all properties such as refraction, anisotropy or sheen. A [shader](#shader) is a particular implementation of a material definition.<br><br><b>Important:</b> The term 'material' is an *umbrella term* used to refer to various things, including:<ul data-preserve-html="true"> <li data-preserve-html="true">The [shader](#shader) used to compute the appearance of a surface or volume;</li> <li data-preserve-html="true">The set of [textures](#texture) provided to a shader;</li> <li data-preserve-html="true">A Material ID, which is an attribute of a 3D primitive used to tell apart the parts that use different materials.</li> </ul> |
| <b><a name="mesh"></a>Mesh</b> | An 3D object made of [vertices](#vertex) connected by edges to form polygons – such as triangles – which in turn are assembled into surfaces. These surfaces may be open or closed.<br><br>The appearance of these surfaces is defined by the [material](#material) assigned to them.<br>The level of detail of a mesh is also highly dependent on its [polycount](#polycount). |
| <b><a name="metadata"></a>Metadata</b> | Data that provides information about the file itself, its environment or anything related to the file's data.<br><br>Common metadata include the file's author, creation and modification dates, copyright and cover art.<br><br>In Designer, the contents of a [package](#package) can also have metadata. For instance, a Substance graph generating a fabric material may have metadata for the fabric's physical properties. |
| <b><a name="mipmap"></a>Mipmap</b> | A smaller version of a texture, often automatically-computed.<br><br>A texture can have a pyramid of smaller versions of itself, which are interchangeable at runtime so that the most appropriate size is used for optimal quality and performance.<br><br>For instance, a texture with high-frequency detail displayed at a smaller size will likely produce *moiré* artifacts. Additionally, a larger texture likely involves more [texture samples](#texture-sampling).<br><br>The term 'mipmap' originates from the MIP mapping technique, where MIP stands for the latin '*multum in parvo*', which means 'many things in a small place'. |

## N

|  |  |
| --- | --- |
| <b><a name="node"></a>Node</b> | Object in a graph that performs computations and outputs one or more results.<br><br>The result is controlled using input parameters. These parameters can be listed as controls in the Properties dock, or as input connectors on the node itself.<br><br>There are two main categories of nodes: [atomic nodes](#atomic-node) and instance nodes. |
| <b><a name="noise"></a>Noise</b> | A non-figurative image representing a random or pseudo-random distribution of shapes and colors. Noises are often used to add variation to surfaces or deformations.<br><br>Designer's node library includes a large collection of noise generators, such as [BnW Spots](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/bnw-spots-2/bnw-spots-2.md), [Clouds](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/clouds-2/clouds-2.md), [Perlin noise](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/perlin-noise/perlin-noise.md) or [Voronoi](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/voronoi/voronoi.md). |
| <b><a name="normal"></a>Normal</b> | In 3D computing, the normal of a surface is a [normalized](#normalization) vector perpendicular to that surface going from that surface outward.<br><br>This vector represents the orientation of a surface in 3D space and is used for [shading](#shader) that surface according to the scene's lights and camera perspective.<br><br>A [normal map](#normal-map) texture can be applied to a surface to modify its normals and add detail. |
| <b><a name="normal-map"></a>Normal map</b> | A texture applied on a surface to modify its normals.<br><br>It is most often used to fake details that would be inefficient to include in a model's geometry. Using such a map allows to have per-texel normals in addition to per-vertex normals, resulting in more surface information and thus more surface detail.<br><br>The X, Y and Z coordinates of the normal vectors are encoded into the map's red, green and blue channels respectively. Depending on the targeted graphics API ([DirectX](#directx) or [OpenGL](#opengl)), the green channel may be inverted. |
| <b><a name="normalization"></a>Normalization</b> | The process of remapping a range of values to the &#91;0, 1&#93; range, where the highest input value is remapped to 1.0 and the lowest input value is remapped to 0.0.<br><br>For vectors, normalization is adjusting the vector's length (or 'magnitude') to a value of 1.0. |

## O

|  |  |
| --- | --- |
| <b><a name="opengl"></a>OpenGL</b> | A 3D graphics API widely used in video game development and other 3D industries.<br><br>OpenGL places the origin of a texture – I.e., its (0, 0) coordinate – at the *bottom left*, (Y-up) whereas the [DirectX](#directx) API places it at the *top left* (Y-down).<br><br>This means an OpenGL normal map has an *inverted green channel* compared to DirectX. Indeed, the green channel hosts the normal vectors' Y-coordinate. |
| <b><a name="openpbr"></a>OpenPBR</b>             | An open-source material model developed by Adobe and Autodesk offering a unified representation of 3D materials across applications and a consistent look across 3D renderers. [This page](../interface/3d-view/material-properties/material-properties.md) provides more details about the implementation in Designer, and the official specification is available [here](https://academysoftwarefoundation.github.io/OpenPBR/).                                                       |
| <b><a name="openusd"></a>OpenUSD</b> | See [USD](#usd). |
| <b><a name="output-format"></a>Output format</b> | [Base parameter](#base-parameter) of nodes in a Substance graph that describes the node's [bit depth](#bit-depth). |
| <b><a name="output-size"></a>Output size</b> | [Base parameter](#base-parameter) of nodes in a Substance graph that describes the node's [resolution](#resolution).<br><br>Learn more about Output size in this [dedicated page](../compositing-graphs/output-size/output-size.md). |

## P

|  |  |
| --- | --- |
| <b><a name="package"></a>Package</b> | A Substance 3D file ([SBS](#sbs-file)) is called a package, in the sense that it is a container for resources: graphs, [bitmaps](#bitmap), [3D scenes](#three-d-scene), etc.<br><br>A package also stores paths to its [dependencies](#dependency) as well as [metadata](#metadata). |
| <b><a name="pattern"></a>Pattern</b> | An image which should be used as a model or reference for producing another image.<br><br>In most cases, a pattern is an image meant to be repeated (E.g., tiled, scattered randomly or arranged according to some set of rules). |
| <b><a name="pixel-ratio"></a>Pixel ratio</b> | This [base parameter](#base-parameter) controls the compensation of the image's aspect ratio at the pixel level. In other words: whether the pixel size should be compensated to conserve a square ratio in a non-square image.<br><br>The parameter is used by non-local filters – I.e., filters which use the values of neighbouring pixels to compute the value of a pixel. |
| <b><a name="pixel-size"></a>Pixel size</b> | This base parameter defines the horizontal and vertical size of a pixel.<br><br>It acts as multiplier for non-local filters – I.e., filters which use the values of neighbouring pixels to compute the value of a pixel. |
| <b><a name="polycount"></a>Polycount</b> | The amout of polygons of a 3D [mesh](#mesh). Indeed, polycount is short for 'polygon count'.<br><br>More polygons can model finer detail. Meshes with a low polycount are called 'low-poly', while higher polycounts are called 'high-poly'. |
| <b><a name="primary-input"></a>Primary input</b> | The input connector of an [instance node](#instance-node) from which that node inherits its [base parameter](#base-parameter) values.<br><br>The primary input is marked with a small dot in its connector, and the '(Primary) suffix in its label.<br><br>When using nodes with more than one input, it is *strongly* recommended to be mindful of which of their inputs is the primary and how it impacts [inheritance](#inheritance) throughout the graph. |
| <b><a name="procedural"></a>Procedural</b> | The chacteristic of an piece of data or artifact to be created by following a computer algorithm, rather than manually.<br><br>Designer uses a procedural workflow where the algorithm is designed as a node graph.<br> <br><br>Procedural workflows allow for faster iterations because variations and adjustments can be quickly generated by modifying the algorithm and its parameters.<br><br>When the result is entirely produced by the algorithm, that result is colloquially referred to as being '100% procedural'. Procedural generation is sometimes shortened to 'proc-gen'.<br><br>Most generators in Designer's node library are 100% procedural in that they require no input image to produce a result. |
| <b><a name="publishing"></a>Publishing (SBSAR)</b> | In Designer, publishing refers to exporting a [package](#package) as an SBSAR archive file which includes [compiled](#compilation) versions of the graphs, their resources ([bitmaps](#bitmap), fonts, etc.), their presets as well as their [metadata](#metadata).<br><br>The resulting SBSAR file may then be distributed and used in other Substance 3D applications or third-party applications through a [Substance 3D plugin](https://substance3d.adobe.com/plugins/). |

## R

|  |  |
| --- | --- |
| <b><a name="renderer"></a>Renderer</b> | A program which processes 3D information such as lights, meshes, and materials to create 2D images. |
| <b><a name="rendering"></a>Rendering </b>(3D View) | The process of computing an image according to input data, using a program such as a [renderer](#renderer). |
| <b><a name="resolution"></a>Resolution</b> | The amount of pixels horizontally and vertically that form a [bitmap](#bitmap). More pixels allow for representing finer detail.<br><br>In Substance graphs, the resolution of a bitmap computed by a [node](#node) is controlled by the node's '[Output size](#output-size)' [base parameter](#base-parameter). |
| <b><a name="roughness"></a>Roughness</b> | A channel of a [material](../glossary/glossary.md) defined using the PBR Metallic Roughness [shading](../glossary/glossary.md) model. Roughness specifies the rugosity of a surface – I.e. microscopic variations of height, also called *microfacets*.<br><br>High roughness results in a matte look, while low roughness results in a smooth, glossy look.<br><br>It is the inverse of [Glossiness](#glossiness). |

## S

|                                                                                                   |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
|---------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b>Sampling</b> (Sample)                                                                          | Acquiring the value of an image or function at a specific point.<br><br>See [texture sampling](#texture-sampling).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| <b><a name="sbs-file"></a>SBS file</b>                                                        | SBS stands for 'SuBStance 3D file'. This file is used to store Substance 3D Designer projects. Its data uses the [XML](#xml) format.<br>See [package](#package).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| <b><a name="sbsar-file"></a>SBSAR file</b>                                                    | SBSAR stands for 'SuBStance 3D ARchive'. This archive file is used to store compiled Substance 3D Designer graphs and the resources they require ([bitmaps](#bitmap), fonts, etc.).<br><br>SBSAR is the main file format used to distribute Substance graphs that are ready to be consumed by other Substance 3D applications and Substance 3D plugins.<br><br>Since the graphs stored in SBSAR files are compiled, they cannot be loaded and edited in Substance 3D Designer. SBSAR files may however be opened using [7Zip](https://www.7-zip.org/) to retrieve their parameters, presets and metadata in an embedded [XML](#xml) file.                                                                                                              |
| <a name="sdf"></a><b>SDF</b>                                                                  | See [Signed distance field](#signed-distance-field).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| <b><a name="shader"></a>Shader</b>                                                            | Program that computes the appearance of a surface or volume according to its [material](#material) properties, the light it receives and where it is being viewed from.<br>A shader is a particular implementation of a material definition.<br><br>Textures may be provided to a shader to drive its behaviour. Raw values may also be used.<br>In the [3D view](../interface/3d-view/3d-view.md), go to the 'Materials' menu to see which shader is being used by a material in the current scene.
